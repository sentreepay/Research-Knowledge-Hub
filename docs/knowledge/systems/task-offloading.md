# Task Offloading（任務卸載）

## 1. 基本概念

任務卸載（Task Offloading）是將 IoT 裝置產生的部分或全部工作交由其他運算設備執行。決策可涉及是否卸載、何時卸載、如何拆分，以及選擇哪個運算目的地。

## 2. 核心原理

卸載決策須比較本地執行與遠端執行的成本。遠端成本除計算時間外，也包括資料上傳及結果下載所需時間；資料量大或頻寬不足時，卸載不一定能降低延遲。

常見分類包括：

- **水平卸載：** 在同一層級設備間分享工作，例如 D2D 或 P2P。
- **垂直卸載：** 在 IoT、Edge、Cloud 等不同層級間轉移工作。
- **二元卸載：** 將單一任務交由一個設備執行。
- **部分卸載：** 將任務拆分成子任務分配到多個設備；子任務相依時須考量等待關係。
- **邊緣資源聯盟：** 由資源控制元件協調不同服務提供者的邊緣資源。

## 3. 主要特色

- 可結合工作拆分、設備選擇及資源管理。
- 常以延遲、能源消耗、資源使用率、負載平衡及服務品質作為決策目標。
- 可採排隊理論、賽局理論、人工智慧、演化式計算或其他最佳化方法；方法須依系統與目標選擇。

## 4. 應用情境

適用於本地裝置資源有限，且可利用鄰近設備、邊緣伺服器或雲端完成工作的 IoT 系統。相關回顧論文以智慧醫療說明將即時監測安排在邊緣、較複雜分析及長期儲存交由雲端的方式。

## 5. 優點與限制

**優點：** 可依設備能力與任務需求分配工作，並利用多個節點的可用資源。

**限制：** 卸載決策可能受網路延遲、頻寬、能源及節點負載影響；任務切分及相依關係會增加協調成本。不同服務提供者之間亦須處理資源協調與安全性。
